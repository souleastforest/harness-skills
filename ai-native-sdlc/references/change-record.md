# 变更记录

用于跨会话推进、多人交接或多阶段工作。优先填入已有 issue、设计记录或任务文档；仅保留改变后续决策的字段，删除不适用项。

```markdown
# <变更目标>

状态：<正在做什么；实现 / 软件验证 / 领域验收 / 发布分别到哪一步>

## 目标与验收
- 使用者与场景：
- 验收条件：<输入 / 操作 / 可观察结果；领域验收人与规则按需列出>
- 范围边界：
- 已确认事实：<来源或证据>
- 假设与待确认项：<什么结果会改变当前方案>

## 当前切片
- 输入与依赖：
- 预期产出：
- 实现选择：<有实际取舍时写原因>
- 风险与验证方式：
- 撤回或恢复方式：<需要时填写>

## 结果与证据
| 验收条件 | 实际结果 | 证据位置 | 缺口 |
| --- | --- | --- | --- |
| <条件> | <通过 / 失败 / 未运行 / 待领域验收> | <日志、测试、产物、版本> | <如有> |

## 下一步
- 下一项动作、执行者与前置条件：
- 需要负责人决定的事项：<仅列真正影响推进的决定>
```

更新当前状态和证据，不靠追加长篇会话记录保存进展。命令退出码、生成文件、软件可用、领域正确、发布成功是不同断言：分别附上足以支持它们的证据。
