# 来源与适配

用于追溯流程依据或调整团队约束。以下是机制摘要和本 skill 的适配判断，文章中的组织实践不自动成为使用者的审批要求。读取情况记录于 2026-09-10。

## 已读取的来源

### The AI-native SDLC playbook

[Anthropic 原文](https://claude.com/blog/the-ai-native-sdlc-playbook)

文章把 Plan、Design、Build、Test、Deploy、Maintain 视为循环：生成代码提速后，计划、验证、评审与维护会成为瓶颈。它强调可版本化的意图、规格、计划与验证工件，简短稳定的仓库上下文，可运行的反馈回路，以及把人的判断放在意图、风险和关键决定上。

**在本 skill 中的适配：** 以一项可验收行为贯通阶段，按现有仓库结构保留必要证据；小任务无需每阶段一份文档。出现新证据时可以返回前一阶段。项目特有上下文留在项目中，通用工作方式留在技能中。

文章还区分提示指导与确定性控制：skill 能引导行为，需要稳定强制执行的规则应由 hook、CI 或工具权限落实。并行修改需要隔离边界；这些机制在实际出现重复流程或并行工作时再采用。

### How Anthropic secures its AI-native software development lifecycle

[Anthropic 原文](https://claude.com/blog/how-anthropic-secures-its-ai-native-software-development-lifecycle)

文章涵盖提示注入、供应链与常规软件漏洞，采用风险分层、确定性扫描和职责有限的 agent 审查，并要求可供复核的证据。工具身份与权限遵循最小权限原则，诊断与部署权限分开；新的自动审查先观察表现，再逐步扩大权限，操作与审批可追踪。

**在本 skill 中的适配：** 用实际影响选择证据深度，涉及权限或信任边界时验证相应失败情形。保留足够定位输入、执行和输出的证据。需要复核时沿用项目责任机制；普通可逆改动直接推进，已有授权继续有效。

若准备让新的自动化承担高影响决策，先在不影响实际决策的条件下运行，比较它的结果与可信基准；确认有效性后再按授权扩大执行范围。诊断成功本身不授予部署权限。
