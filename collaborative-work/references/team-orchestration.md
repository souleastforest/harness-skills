# 团队编排模式

用户明确启用团队编排，或当前会话、可访问的项目权威记录已有约定时读本页，不要求特定口令。无法读取其他会话的约定时，沿用普通协作。用户可以调整或关闭模式。

## 先定职责，再选模型

- **主控**负责方向、任务分派、目标与授权边界、证据审查和用户沟通。检索文件或网络、编辑代码及运行命令交给代理。要求代理提供出处、相关原始片段、产物和验证依据，必要时委派独立核对，再判断证据支持哪些结论。
- **调研**检索文件、资料与网络，整理事实、核对来源和不确定性。只读任务保持只读。
- **实现**完成获授权的产物和必要验证。委派时写清负责范围、允许动作、交付物和停止点，说明共享工作区中还有其他人。保留他人修改，遇到相关变化时适应并报告影响。

代理数量按任务需要选择，小任务可只派一名执行者直接完成。主控先凭证据和已有共识处理技术分歧，只有新目标、范围、重要代价或用户偏好等取舍才带回用户。

查询状态、等待或读取消息时，限定到本轮已获准协作的任务。工具支持任务 ID 或路径前缀时，使用相应筛选；不要通过全局清单顺带读取无关任务及其反馈。无法限定读取范围时，等待已分派任务返回，或说明缺少所需能力。

## 模型与思考强度分别选择

优先遵循用户对当前任务指定的角色、模型与 effort，再沿用已确认的会话或项目约定，并核对当前宿主实际提供的能力。角色定义职责，model ID 选择模型，reasoning effort 单独设置；根据宿主可用选项匹配，不用 `pro`、`flash` 等名称猜测型号或档位。

没有指定型号时，选择宿主合适且可用的模型，必要时简短说明。主会话模型、宿主配置、依赖和 provider 保持现有设置，调整它们需有对应授权。

指定的模型或 effort 不可用、无法选择，或宿主缺少所需委派能力时，说明限制并暂停相关委派，请用户决定替代方案或调整模式。保留原有分工，主控不自行接管执行。无法确认实际模型时，分别说明请求参数与可验证的运行信息。

以下是偏好示例，实际选择仍按上述优先级和本会话能力确定。

- **Codex**主控沿用当前主会话；实现请求 `gpt-6.1-sol`，effort 为 `max`；调研请求 `gpt-6-luna`，effort 为 `xhigh`。
- **Claude Code**主控 Opus、实现 Sonnet、调研 Haiku。具体版本与 effort 取宿主支持项及用户指令，另行核对与 Codex 的差异。

这些示例未作为跨宿主验收结果，也不构成安装依赖。

## 启用后沿用约定，边界仍由本轮控制

沿用已确认的角色、模型和决策节奏。需要保存时，在当前上下文或已有项目权威记录中写入必要约定，并遵守该处写入规则。跨会话记忆、新 profile、配置或台账需有相应需求与授权。

团队模式沿用本轮范围；组织实验需要已有明确实验授权，启用模式或认可计划本身不增加这项许可。部分阻塞、改意、全停与收尾仍按主技能执行。Matt 保留人工入口和整份规格要求；brainstorming 按需用于讨论，团队模式不自动启动其他执行链。
