# collaborative-work 0.5.0 验证记录

2026-10-26。本轮完成发布工具、任务评估和本机安装回退演练。结果支持在下述 Codex 环境继续试用；尚未建立跨宿主、跨模型或长期稳定性结论。

## 交付内容

- [运行插件](../../plugins/collaborative-work/README.md)：保留 start、help、brainstorm、complexity、develop、story、team、maintain、matt 九个入口。start 的默认提示改为有任务就推进，无任务才介绍。软件开发仍是专项，团队编排仍需显式启用。
- [发布工具](../../tools/collaborative_work/README.md)：声明并锁定依赖，校验布局、版本、链接、文件散列、原生发现与精确缓存来源；生成和验证可复现 ZIP。同版本不同字节会被拒绝。
- [评估材料](../../evals/collaborative-work/README.md)：8 个行为任务、22 条元数据路由查询、原始附件和单独保存的判据。运行记录与评分隔离，失败不覆盖。
- [CI](../../.github/workflows/collaborative-work.yml)：使用与本机相同的单元、结构、构建和包验证入口。运行插件不包含发布脚本、MCP server 或 hook。
- 新增内容采用 MIT；[第三方说明](../../plugins/collaborative-work/THIRD_PARTY_NOTICES.md)保留 Superpowers、Matt Pocock 的许可与固定来源。研究材料和课程原文件没有随包分发。

本轮实际环境为 macOS 14.4.1 arm64，桌面随附 Codex CLI `0.164.0-alpha.11.1`。工具环境为 Python 3.14.2 freethreaded，依赖由 uv 0.9.20 和锁文件安装。CI 另设 Linux / Python 3.13，但尚未在 GitHub 运行。

行为会话导出记录的设置为 `gpt-6.1-sol`、`ultra`，使用相互隔离的新子会话。它们继承宿主常驻说明和技能元数据；不是完全空白的环境，也未独立验证后端模型身份。任务执行者没有获得判据或其他运行结果。

case01 模拟各版本实际选择器默认提示，用户任务与原始附件相同，但整条输入因默认提示不同而不同。其余 case02–08 请求字节相同。两版均完成 case01 标题修改；候选回复更短，不据此宣称失败率改善。case06 没有独立保存完整能力清单，因此“指定占位模型不可用”的事实仍有证据缺口；没有替代模型或主控接管则可从动作轨迹观察。

## 发现过的问题与处理

独立代码审阅在原有50项测试通过后，仍实际复现了两项问题：原生探测的报告输出可覆盖源清单或经链接覆盖缓存；正则链接扫描漏掉合法嵌套标签。修复后，报告只能独占创建在受检树之外的新文件，链接检查改用 CommonMark 解析器。审阅者重跑原攻击：覆盖路径提前失败且输入字节不变；嵌套逃逸链接在 validate、build、verify 三个入口均失败。新增13项针对测试后，全套63项通过。

初轮候选故事自选广义 Tikhonov 正则化，理论自洽，但没有查询来源，未满足宿主对专业主题的核实要求。原失败保留，随后只补充故事参考中的来源核查条件。相同原始请求的两次复跑实际打开大学讲义，解释、隐喻和理论条件对应，引用放在故事后。两次自选主题均变为拉奥—布莱克韦尔定理，没有把它们写成对初轮 Tikhonov 内容的补验。

一次复跑的模型自存 answer.md 把两处数学转义写成制表符，实际最终消息正常；另一轮保存修正曾出现 AssertionError，随后恢复。原始文件和失败轨迹保留，另从最终助手消息提取新的 delivered-final.md 并核对散列。不能把最终回复正确说成所有自存证据文件都无误。

安装后无入口提示的故事试用实际读取了旧 standalone `0.3.0`。旧副本12文件经核对与已发布版本一致后，整体移至发现目录之外备份；0.5.0插件缓存未变。随后显式指定已安装的0.5.0 story入口，实际读到该版 story、start及故事参考，完成给定材料任务。现有线程可能仍持有旧目录元数据；本轮没有证明真正新建桌面聊天的自动选择行为。
