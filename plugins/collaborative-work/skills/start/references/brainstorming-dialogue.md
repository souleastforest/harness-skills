# 把影响结果的重要未知谈清楚

目标或方案需要探索时读本页。已有共识足够，或只是明确的小改动，就沿用主技能直接处理。

## 从具体情境理解背景

先读当前对话与获准使用的项目材料，弄清目的、使用者、成功条件、不能接受的结果，以及约束和现状。能查明的事实先查，只把影响下一步的缺口带回用户。

缺少使用情境时，可请用户「讲一次你最希望它已经存在的时刻」；担心误解时，可问「什么结果会让你觉得做错了」。选一个符合当前缺口的具体问法，沿用用户的词汇。

## 先筛路线，再帮助用户选择

根据目标和约束筛选路线，只展示仍有意义的少量选择，说明适用条件、收益与代价，再给出推荐。只有一条合适路线时，解释依据即可。

用户决定会影响结果的偏好，助手负责实现默认值。沿用现有环境中合适的做法，说明哪些是助手的判断。技术事实和设置由助手核实。

## 及时回放理解

一个重要设计点能说清时，用短段落回放理解与理由，分清已定决定、暂定意向、助手选择和假设，给用户纠正的机会。每轮聚焦一个影响后续工作的决定，回放长度和是否提问取决于实际需要。

前提相互冲突或需求超出本轮范围时，说明影响，暂停相关部分，继续独立且已授权的工作。范围变化按主技能处理。

## 判断是否足够继续

检查接手者是否还需要猜测会影响方案的信息。已有材料能回答的就补入理解；不会改变目标的实现细节留给执行者；需要用户偏好的未知再带回讨论。这次判断由助手完成，无须固定增加审稿代理。

重要未知已解决，或可在既定范围内处理，就回主技能形成必要计划。交接只保留接手者需要的背景、成功与失败条件、约束、决定、待解问题及可自行判断的部分，附上本轮授权、验收与停止条件。沿用对话或现有权威记录，需要持久交接时再保存文件。

暂定、暂留和认可计划不自动扩大授权。当前及此前的明确授权继续有效；讨论产生新范围或取舍时，只处理受影响部分。

## 适配边界与来源

本地适配采用按需讨论、必要计划和已有授权连续执行。原版的完整访谈、逐条提问、书面设计审批、强制 spec/commit、fresh builder 审查及自动 `writing-plans`/执行链均未接入。普通文字和已有内联可视化可按需使用；视觉服务器、持久服务和 spike/实验仍需符合本轮授权。讨论后回主技能，选用 Matt 时再读其接入参考。
