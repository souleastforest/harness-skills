# 开发和维护技能

用户要求创建、修改、评估或发布技能时读本页。普通任务只使用技能的运行指引。沿用已有技能开发工具和仓库约定，按本轮改动选择检查范围；本技能的首版验收以 Codex 为范围。

维护本插件源码时，使用源码仓库的 `tools/collaborative_work` 和 `evals/collaborative-work`。从声明的 uv 环境执行结构校验、工具测试、构建与包验证，再检查实际安装和受影响行为。工具和评分材料不随运行包分发；它们缺失时先定位真实源码，不在安装缓存里临时改出一个同版本副本。

## 保存基线，确定要改的行为

修改前保存当前安装的完整字节副本，记录文件清单、校验值、来源和日期。仓库版本与安装版本不一致时分别保留，确认哪一份作为比较基线。许可证和来源文件随版本保存。

从真实请求或代表性场景说明希望改善的行为，以及需要保留的能力。把每项规则改动对应到问题，优先修正触发条件或有歧义的指令。授权边界、用户决策权等实质变更沿用用户已经确认的范围，超出范围时再讨论。

## 先写验收场景

在修改提示词前写下任务材料与通过条件。选取本轮变化会影响的分支，通用协作能力至少考虑明确小任务、已授权的复杂任务和非编程任务；涉及编排、改意、交接或能力缺失时加入相应场景。

通过条件描述可观察结果，例如文件是否正确修改、是否越过研究范围、是否重复索要已有授权、接手者能否继续工作。避免用固定话术、标题数量或提及流程名称判断质量。重要失败单独记录，即使其他场景通过，也要处理越权操作、丢失用户改意或虚报验证等问题。

本技能的维护材料放在源码仓库的 `reviews/collaborative-work/`，包括场景、评审标准、基线和运行证据。安装包只包含运行指引及必要资源。执行验收任务的会话仅获得用户请求、待测技能和必要原始材料；评审标准与历史答案留给评审者。

## 制作候选版本

在独立目录修改，保持本地安装可用。共同规则留在入口，专项细节放在按需加载的参考页；检查入口的触发条件是否能到达所需材料。用户要求自然语言润色时，删去空话和重复说明，保留技术含义、命令、链接和机器读取字段。

先检查元数据、文件引用、许可证、依赖声明、未完成占位和规则冲突。运行新增或修改的脚本，检查其实际结果。静态检查通过后，才进入需要该版本的行为验证。

## 独立运行与评审

基线和候选版使用相同的任务材料、可用工具和环境，各自在新的独立会话与隔离工作目录中运行。若宿主支持无历史继承的代理，使用该方式；否则如实记录上下文可能造成的影响。给执行者真实任务，避免同时传入预期答案、待修问题或其他运行的结论。

多轮场景需要实际提供后续输入。验证中途改意时，在相关工作尚未完成时传入修改或停止要求；验证交接时，由新的接手者只凭交接和允许使用的材料继续。预先写在单条请求中的限制只能验证读指令的行为。

保存每次运行的技能校验值、任务输入、宿主与可确认的模型设置、实际操作记录、产物和检查结果，失败运行也保留。评审者将预先写好的标准与这些证据对照；优先独立评审，人工或主助手评审时说明方式。检查行为是否正确，也检查新增流程是否拖慢小任务或损坏原有能力。

根据观察到的失败做定向修订，再复跑受影响场景。对易波动的改意、编排与跨会话场景重复运行；重复次数和环境写入记录。通过条件已满足时结束本轮，仍有失败则报告原因和限制，不靠不断换措辞宣布通过。

## 区分检查结果

维护报告分别写明下列证据，结论限定在实际测试范围内。

| 检查 | 能支持的结论 |
|---|---|
| 静态检查 | 文件结构、元数据和引用符合已执行的检查 |
| Codex 装载 | 独立会话确实读到了指定版本；记录读取证据，显式加载与自动发现分开说明 |
| 行为验证 | 指定环境和场景中观察到了哪些行为，以及哪些失败或尚未测试 |

读到了文件不能证明自动发现成功，一次任务通过也不能证明跨宿主稳定。报告所用版本、场景与限制，随后续真实使用积累证据。

## 更新本地安装和回退

在用户授权更新的范围内发布。赋予候选版可追溯的版本标识，保存它对应的校验值和验证记录。替换前重新比较本地安装与基线；若期间出现新修改，先保留完整副本并处理差异。

把旧版备份放在技能发现目录之外，避免 Codex 同时发现两个同名技能。先将候选包复制到暂存位置并核对，再替换目标目录；替换失败时恢复旧目录。只安装运行所需文件，评测材料和旧版留在维护目录。

更新后核对安装内容与已验证候选版一致，再用新的 Codex 会话实际加载该安装路径并完成小范围行为检查。保留旧版、候选版、安装路径和恢复步骤，说明当前会话可能仍持有旧指令。

回退时先保存安装后新增的本地修改，再恢复指定旧版并核对校验值。用新会话加载恢复后的版本，记录回退原因和结果。首次发布或后续维护都按实际验证声明支持范围，其他宿主经过相应验证后再加入。
