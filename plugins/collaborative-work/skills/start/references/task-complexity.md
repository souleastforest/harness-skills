# 选择够用的工作流程

在任务需要多个关联步骤、重要未知尚未解决，或工作要跨阶段接续时阅读。先用已有材料判断，再决定需要补多少研究和计划。

## 判断什么

关注目标是否清楚、现状是否熟悉、步骤间的依赖、改动影响和验证条件。文件数、文字长度、预计耗时只作线索。一次数据库字段修改可能涉及历史数据和外部调用；一份很长但规则明确的排版任务也可能直接完成。

先查能查明的事实。对结果影响很小的实现选择，由助手作合适默认；涉及用户目标或重要代价的取舍，按主技能返回用户。

## 四种处理方式

| 当前情况 | 处理方式 | 完成依据 |
| --- | --- | --- |
| 目标清楚，改法已知，影响局部且结果容易核对 | 直接执行并检查 | 约定产物已改变，受影响内容已核对 |
| 目标和做法清楚，有几个关联步骤 | 用简短计划安排依赖，再执行和验证 | 步骤完成，结果符合验收要求 |
| 不熟悉现状，或关键事实会改变方案 | 研究相关材料，比较有意义的路线，再计划、执行和验证 | 方案有事实依据，结果可核对 |
| 依赖跨度大，需多个阶段或会话完成 | 划分可验证的阶段，每阶段按需要研究、计划和执行 | 阶段成果可检查，下一阶段能凭记录接续 |

计划可以放在对话里。任务已有规格、检查单或权威记录时，更新原处。决定采用分阶段流程时，说明近期阶段的成果和返回条件，不提前编造远期细节。

## 根据新证据调整

研究发现问题比预期简单，就缩短后续流程。发现共享接口、未知使用者或新的依赖，就补充相应研究和验证。调整影响用户目标、范围或重要代价时，再提出需要用户决定的部分。

流程深度与授权分开判断。明确的复杂请求可以连续执行；只授权调查的小请求仍应止于调查。团队编排也有独立的启用条件，依主技能和团队参考执行。

## 不同任务中的用法

把已指定标题换成另一个标题，直接修改并核对即可。为一个小网站增加两个已明确的页面，通常需要短计划。接手陌生项目修改计费规则，先查规则、调用方和测试，再确定方案。跨系统替换登录机制，需要按依赖拆阶段，并为每阶段保留验证结果。

整理已给材料中的会议日程，可以直接处理。策划活动时，先消化预算、人数和场地；只有无法从材料确定且会改变方案的偏好才需要问。非编程任务根据产物选择核对方式，软件开发参考只在适用时加载。

## 交接时保留什么

为下一阶段留下目标和授权边界、已定决定及理由、实际成果和证据、未解问题、剩余依赖与下一步。记录引用准确文件或产物，摘要中的事实要能回查。

在阶段结束、即将更换会话，或宿主提示上下文容量不足时整理交接。按需加载原始材料；课程中的上下文比例是提醒，不作为跨模型通用阈值。接手者先核对当前文件和实际状态，再沿用仍有效的记录。
