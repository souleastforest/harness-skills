# 面向读者的技术文档

让目标读者理解问题、找到起点，并能判断结果。保留原意、证据强度、授权边界和验证
结论；语言、篇幅与交付形式服从用户要求和现有文档约定。

## 按阅读任务选择写法

先从请求和材料确定读者、阅读目的与已知条件。局部改写只应用相关方法，保留可用的
结构；新写或整体整理时，再交代读者将得到什么、需要什么前提。

- **动手完成任务**：教程带着走通一个过程；操作指南解决一个具体问题。使用下文的实践步骤。
- **理解或作判断**：概念页解释对象、关系与边界；背景页解释方法和取舍。例子服务于理解。
- **查准确信息**：参考页让字段、接口和约定容易定位，保留精确名称、取值与限制。

短文可合写；只有阅读目的确实不同且内容足够多时才分开。需要多页导航时，链接说明
为什么要读，如“理解这些名字，读……；开始一次试跑，读……”。

## 让读者跟得上正文

- 对目标读者陌生的项目术语，首次出现时先解释作用或关系，再连接英文或代码名；
  后文保持同一称呼。精确标识放在读者需要查找、配置或执行的位置。
- 教学叙述先建立对象与关系，再展开字段和版本细节；概念较抽象时，用一个贯穿例子。
- 标题帮助读者定位：操作页用动作或问题，参考页可直接用准确的字段或接口名。
- 段落围绕一个问题展开，把行动与目的、结果与含义连起来；列表、表格和流程图用于
  比较、查询或辅助理解，按阅读任务选择，不把句子固定成同一种顺序。

## 写出能实践的步骤

对文档中的每个实践步骤，让读者能找到这些信息，简单步骤可合写：

- **起点与动作**：说明所需输入、操作位置和本步目的。涉及命令时注明工作目录、
  文件位置和占位符的替换方式，用现有实现支持的最小动作。
- **可观察结果**：说明在哪里看到什么，以及它能证明什么。后续步骤接续本步产物。
- **失败入口**：对已知常见失败，就近给出症状、检查与恢复办法；复杂分支链接专页。

人工检查、选择输入、提取经验同样可以构成实践步骤。标明示意输出与实测结果；区分
文件已准备、实际装载、行为发生与质量通过，结论只到证据支持的层级。缺失入口或
未经验证的行为如实说明。受控失败或对照例子仅在帮助理解时加入。

## 整理已有文档

- 在本次整理范围内，让同一规则有一个权威位置，其他页面链接接续。
- 教程讲可复用过程；持续变化的状态链接到项目已有的台账或检查点。
- 任务涉及文件重组或归档时，先核对引用，沿用项目既有保存与兼容约定；涉及冻结
  证据时保留其原文与来源关系。普通改写无需建立归档、哈希或状态管理机制。
- 按源码、配置和现有证据核对技术事实，保留影响操作或判断的权限、失败与计量约定。
  文档核对不自动授权运行其中描述的安装、发布或实验操作。

## 交付前按读者视角检查

按实际文档形态检查：实践页能否开始并判断完成，概念页能否说明对象关系与适用边界，
参考页能否迅速查到准确约定？核对本次改动涉及的命令、路径、局部链接与事实依据；
验证受限的内容标明范围。流程尚需继续时，给出接续当前成果的下一步。

需要结构示例、改写对照或来源依据时，再读 [Cordis 写作参考](references/cordis-patterns.md)。
