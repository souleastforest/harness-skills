# 睡眠截图入档（V1.1）

处理用户手动提供的一张或多张睡眠截图。当前 Agent 直接读图，核对同一晚的事实，
保留原图并写入个人中枢。首次入档引导设置，以后复用；自动采集留给后续版本。

## 从本次意图开始

读取 [睡眠记录 V1 合同](references/sleep-record-v1.md)。字段、归属日期和更正
语义以该文件为唯一规范。仅解析截图或预览字段时直接读图，无需初始化目录或 Git；
回复中明确尚未入档。首次需要写入、归档，或用户明确重新初始化时才进入向导。

## 配置与目标

本机设置位于 `$XDG_CONFIG_HOME/sleep-screenshot-log/config.json`；未设置 XDG
目录时使用 `$HOME/.config/sleep-screenshot-log/config.json`。用当前操作 backend
的工具读取，个人路径与配置只留在该主机。

按以下优先级确定个人中枢的 `self_root`：

1. 用户本次明确指定的绝对 `self_root`。
2. 当前运行环境中非空的 `SLEEP_SELF_ROOT`，其值也须为绝对路径。
3. 有效本机配置中的 `self_root`。

`SLEEP_SELF_ROOT` 是本 skill 约定的普通环境变量，不是 Hermes 原生配置项，也不会
自动注入 prompt。用当前宿主可用的 terminal 工具实际读取它，例如
`printenv SLEEP_SELF_ROOT`，不转储整个环境。
高优先级值无效时先修正该值，不静默回退。Linux 使用当地实际可访问的路径。

配置缺失、损坏、目标换成新 root，或用户明确要求初始化：读取
[引导式初始化](references/initialization-v1.md)，只读探测，集中展示推荐并取得一次
确认后再创建目录、保存配置或处理 Git。旧配置只能给新 root 提供候选策略。配置
有效且目标未变时直接复用，日常不重问；不为只读预览触发这些操作。

复制或写入前，用实际执行操作的 file/terminal 工具 backend 检查原图可读、目标
目录可写；尚未建目录时检查其现有父目录可写。路径须对该 backend 可访问。

## 读图与核对

优先由当前 Agent 使用自身视觉能力读原图；确无读图能力时才使用当前环境可用的
vision 工具，不指定外部供应商。工具仍无法辨认时，保留未知并说明缺口。

将同一晚的多张图合并理解，按合同整理已显示的指标与有出处的上下文。把 App
建议、广告、跨日洞察和主观感受与单晚事实区分开；只有用户明确提供的感受才可记，
不从分数推断感受。
完成分钟换算、分期合计和时间跨度核对；差值与异常按合同处理，不自行修正来源值。

## 保留证据并入档

- 将原图字节复制到 `health/_raw/sleep/YYYY-MM-DD/`；按内容哈希识别已有副本，
  复用相同证据并保留新证据。编辑后的预览不能替代原图。
- 以 `health/sleep/YYYY-MM.md` 为唯一睡眠事实源。先读已有月档，按合同的日期
  主键新增或更新一个日期小节；保持其他日期与手写内容。原图复制成功后才引用它。
- 在 `02-life.md` 的现有睡眠小节维护月档链接或索引，保护已有生活内容；文件缺失
  时可创建最小索引。更正归属月份时同步链接，指标与感受只查月档。
- `health/YYYY-MM.md`、`health/_index.md`、`health/_raw/records.json` 由健身
  Base 导出脚本重写，本流程不写它们。已有训练、体重的 Base 录入规则保持原样。
- 已启用复核或归档时，按 [已确认的存储策略](references/initialization-v1.md#截图复核与归档)
  在本次手动调用中检查候选。归档只生成无损 ZIP 副本，散图与原证据链接继续保留。
  Git 初始化不等于提交许可；本技能默认不自动提交、推送或创建后台服务。

## 完成检查

回读月档，确认每个日期只有一条记录，证据链接可解析、原图哈希一致，重复输入
没有增加记录或重复引用。确认 `02-life.md` 只改了睡眠链接或索引。

回复已写入的醒来日、简短结果、月档和证据位置，以及仍未知或待核的项目。只有
实际完成写入才说已入档；若仅解析完成，明确说明尚未保存。
