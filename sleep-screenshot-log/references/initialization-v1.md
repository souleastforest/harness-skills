# 引导式初始化 V1

本页定义本机配置与首次设置，不改变 [睡眠数据合同](sleep-record-v1.md) 的字段或
`contract_version=1`。包版本、配置版本和记录合同版本分别维护。

## 先探测，再集中确认

需要首次写入或归档、配置缺失/损坏、换了 root，或用户明确重新初始化时使用本页。
只读预览不要求配置。确认前只检查路径、现有设置与 Git 状态，不建数据目录、配置
目录或仓库，不复制图片。按 `SKILL.md` 的优先级选择目标；高优先级路径无效时
报告并修正它，不能转而写入低优先级位置。

用同一个工具 backend 检查目标是否存在、原图是否可读，以及目标或最近的现有父
目录是否可写。只在已知位置寻找现有 `self`，不遍历个人目录。目标不存在时，从
最近的现有父目录探测 `git rev-parse --show-toplevel`，检查它是否属于父仓库。
目标已在仓库内则读取其顶层路径、相关 ignore 和已跟踪媒体的路径，不读 Git
身份或带凭据的 remote URL。

用一张简短设置卡集中展示以下候选，让用户一次确认或一并修改：

| 项目 | 默认推荐 |
| --- | --- |
| 数据目录 | 复用用户已有的 `self`；没有已知目录时推荐当前用户 home 下的 `personal-data/self`，展开为该主机绝对路径；不用 skill 安装目录 |
| 时区 | 沿用用户已知的 IANA 时区；无法确定时在这轮询问，不猜 `Asia/Shanghai` |
| 月档 | 结构化月档长期保留 |
| 截图 | 原图长期保留；也可选 7/30/90 天等后复核或进入归档候选，分别说明用途 |
| ZIP | 默认关闭；可选对已结束月份做无损 ZIP 副本，先保留全部散图 |
| Git | 已有仓库可复用；没有仓库时默认不新建，可明确选择创建本地仓库 |
| 自动动作 | 不自动删除、不自动提交、不推送、不建定时后台服务 |

例如：“建议用 `<实际绝对路径>`、`<已知时区>`，月档和原图长期保留，暂不压缩；
`<复用现有仓库 / 暂不建 Git>`，手动提交、不推送。是否按此初始化？可一并改目录、
时区、截图复核天数、ZIP 或 Git 选项。”若同一条消息已完整给出路径/选项并明确
“按这些创建/我确认”，就直接落实，不再要求答一次确认。用户修改并明确同意的
回复也是确认；有关键缺项只补齐该项，不重开整张问卷。

有限天数只表示复核/归档候选时间，不是最长物理留存保证，也不授权删除。V1.1
不清理散图；若用户要求彻底删除或归档后删散图，保留现状并单独说明需要另定策略。
本地 Git 不加密；同盘 ZIP 是归档副本，不是异地备份。可基于本次输入大小提供粗略
容量估算，说明假设，不把样本大小当作未来保证。

## 本机配置

在当前 backend 实际读取 `XDG_CONFIG_HOME`。非空时须是绝对路径；未设置时使用
当前用户 home 的 `.config`。配置文件为该目录下的
`sleep-screenshot-log/config.json`，不是 Hermes `config.yaml` 项，也不会自动注入
prompt。确认后才创建配置父目录，以临时文件加原子替换保存；保持其他应用配置。

以下仅为合成示例，不是要写入用户主机的默认实值：

```json
{
  "config_version": 1,
  "self_root": "/home/example/personal-data/self",
  "timezone": "Asia/Shanghai",
  "screenshots": {
    "raw_review_after_days": null,
    "archive_after_days": null,
    "keep_raw_files": true,
    "delete_after_days": null
  },
  "git": {
    "enabled": false,
    "auto_commit": false,
    "remote": null
  }
}
```

- `config_version` 固定为 `1`，`self_root` 为绝对路径，`timezone` 为有效 IANA 时区。
- 两个 `*_after_days` 候选值可为非负整数或 `null`：复核天数为空表示不提醒；归档
  天数为空表示关闭 ZIP，整数表示启用月度 ZIP 候选。天数从本机首次入档/副本保存
  时间计算，不从历史睡眠日期算；刚补录旧夜不能被当作已保存几个月。
- V1.1 只支持 `keep_raw_files=true`、`delete_after_days=null`。其他值不作为删除
  指令执行，应进入策略修复。记录月档长期保留，不因截图策略变化而删除。
- `git.enabled` 是是否使用 Git 的选择；初始化保存 `auto_commit=false`、
  `remote=null`，不改变现有仓库的 remote。另行提交或发布需要对应任务授权。

首次保存后回读校验。下次配置有效且实际目标相同就复用。换 root 时，旧配置值可
作推荐，但须重新确认新目标的存储与 Git 选择后才写入新 root 和更新设置。损坏
配置保留原文件，确认修复前不覆盖；有效配置被重新初始化时，只改本技能设置。

## Git 初始化

确认后才创建数据目录和必要的睡眠子目录。Git 选择关闭时不运行 `git init`。
选择启用时重新探测：目标处于已有仓库（包括父仓库）便复用，绝不嵌套初始化；
没有仓库且用户明确选择创建时，才在 `self_root` 创建本地仓库。

推荐本技能只跟踪 `health/sleep/` 内的结构化月档。把散图与 ZIP 加到实际仓库
根的 `.gitignore`，路径按该仓库根到 `self_root` 的相对位置计算并正确转义，
保留原条目和用户注释。例如 root 位于仓库的 `self/` 时添加：

```gitignore
/self/health/_raw/sleep/
/self/health/_archives/sleep/
```

若 `self_root` 就是仓库根，则去掉规则中的 `self/` 前缀。先检查相关媒体是否已被
跟踪：ignore 不会让已跟踪文件或历史消失，须明确报告事实，不自动 untrack、删历史
或改写提交。初始化不 stage 或 commit；保留用户已有 staged 改动，不用 `git add .`，
不改全局/现有身份，不添加 remote、不推送。以后用户单独要求提交时，只 stage
本次明确授权的结构化文件；已有仓库的其他跟踪范围保持原样。

## 截图复核与归档

默认无到期任务，散图长期保留。设置复核天数后，只在用户手动调用或日常入档
自然运行时简短提示达到天数的自管证据；不重复初始化提问，不注册通知或后台任务。

设置归档天数后，同样在手动运行时处理已结束月份；拟归档证据在本机的已保存时长
须都达到候选天数。`recorded_at` 只有在能确认该批证据首次同批保存时才可作依据；
后补图片或迁移后的保存时间不明时标为未知，只列候选，不用醒来日或输入文件的
旧时间戳补算。无需增加逐图 TTL 表。因此不会承诺第 N 天准时归档。只收集月档实际引用、位于
`health/_raw/sleep/` 且哈希核验通过的自管副本，不处理用户提供的输入原件。

每月生成 `health/_archives/sleep/YYYY-MM.zip`。ZIP 内保留相对 `self_root` 的
原路径及原始字节，并放一个 `manifest.json`：记录 `format_version=1`、
`created_by="sleep-screenshot-log"`、`sleep_month`，以及各文件的相对 `path`、
`sha256`、`size_bytes`。不写原始输入的机器绝对路径。

先写临时 ZIP，再检查 CRC、逐文件 SHA-256 和成员清单；核验可恢复后才发布。已有
同内容的有效归档直接复用；需要补入新证据时，仅原子替换能由 manifest 明确识别
的本技能归档。遇到其他同名文件、坏归档或源文件缺失时保留原物并报告，不覆盖。
归档失败不影响已经核验并保存的散图和月档，可稍后重试。

ZIP 只作额外副本：不删除散图，不更改 `evidence_refs`，不降低原图字节与哈希校验
要求。回读所有证据路径，确认归档后仍能直接访问原图。无需新增 archive locator
或改动睡眠数据合同。
